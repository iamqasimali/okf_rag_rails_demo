# Extending Knowledge

This app has two knowledge stores. Choose the one based on the kind of answer
you want the agent to give.

- Use OKF markdown for canonical facts, policies, pricing, compliance, and
  anything agents should not improvise.
- Use RAG chunks for messy support history, troubleshooting notes, tickets,
  transcripts, logs, forum posts, and examples where similarity search is useful.

## Add A New OKF Markdown File

OKF files live under `knowledge/`. Each file is one concept with YAML
frontmatter followed by markdown body text.

Example:

```md
---
type: policy
title: Workspace Transfer Policy
description: Rules for transferring workspace ownership.
resource: "flowbase://policies/workspace-transfer"
tags:
  - workspace
  - transfer
  - ownership
  - policy
timestamp: "2026-07-07"
---

# Workspace Transfer Policy

Flowbase allows workspace ownership transfer only when the current owner or a
verified company admin approves the change in writing.

If the current owner is unavailable, support must escalate to
[Escalation Path](../support/escalation-path.md).
```

Recommended location:

```text
knowledge/policies/workspace-transfer.md
```

Then make it discoverable by linking it from a nearby index file:

```md
- [Workspace transfer policy](workspace-transfer.md)
```

For the example above, add that link to:

```text
knowledge/policies/index.md
```

## OKF Frontmatter Rules

Required:

- `type`

Recommended:

- `title`
- `description`
- `resource`
- `tags`
- `timestamp`

The router relies heavily on `tags`, so add the exact words users are likely to
ask with. For example, a refund concept should include tags like `refund`,
`billing`, and `cancellation`.

Supported concept types are not hardcoded, but the router currently gives
preference to concepts with:

```yaml
type: policy
```

Use `type: collection` for index pages and `type: policy` for answerable
canonical documents.

## Verify A New OKF File

Run:

```sh
bin/rails runner 'puts OkfConcept.load_all.map(&:title)'
```

Then ask a matching question in the UI. For example:

```text
Can I transfer workspace ownership if the owner left the company?
```

Expected UI result:

- Badge: `OKF - Curated`
- Source: your new concept title
- Context drawer includes the markdown body

If the router does not pick your concept, add clearer tags or update
`TAG_SYNONYMS` in `app/services/knowledge_router.rb`.

## Add RAG Data From Ruby Seeds

RAG records are stored in the `knowledge_chunks` table. Each chunk needs:

- `source`: stable unique-ish label, such as `TICKET-2042`
- `content`: plain text support-history snippet
- `embedding`: generated by OpenAI embeddings

For small demo snippets, add rows to `RagSeedData::BASE_SNIPPETS` in:

```text
app/services/rag_seed_data.rb
```

Example:

```ruby
[ "TICKET-2042", "A customer fixed Intercom webhook failures by rotating the shared secret and replaying the failed event batch." ]
```

Then run:

```sh
bin/rails rag:seed
```

The seeder skips existing records by `source`, so use stable source names.

## Add Large Synthetic RAG Data

For load testing retrieval with more rows:

```sh
bin/rails 'rag:seed_large[300]'
```

Change the count as needed:

```sh
bin/rails 'rag:seed_large[1000]'
```

This uses generated support-history notes from `RagSeedData.generated(count)`.
It is useful for demo and retrieval testing, not production content.

## Add RAG Files

The app does not yet include a file-ingestion UI. The current production-shaped
path is:

1. Read files from a folder.
2. Split them into chunks.
3. Pass `[source, content]` pairs to `RagSeeder`.
4. Let `RagSeeder` batch embeddings and insert `KnowledgeChunk` rows.

Example Rails runner script:

```sh
bin/rails runner '
  files = Dir.glob(Rails.root.join("rag_files/**/*.txt"))
  snippets = files.flat_map do |file|
    text = File.read(file)
    text.scan(/.{1,1200}(?:\s+|\z)/m).each_with_index.map do |chunk, index|
      source = "#{Pathname(file).relative_path_from(Rails.root.join("rag_files"))}##{index + 1}"
      [source, chunk.strip]
    end
  end

  inserted = RagSeeder.new.seed(snippets)
  puts "Inserted #{inserted} chunks"
'
```

Suggested folder:

```text
rag_files/
  tickets/
  transcripts/
  forum_posts/
```

Do not put highly sensitive production data into this demo app. If you ingest
real files, remove secrets and customer personal data first.

## RAG File Format Guidance

Good RAG content:

- One issue, workaround, or observation per chunk.
- Includes product/integration names users may search for.
- Includes symptoms and actual resolution.
- Has a stable source label that can be shown in the UI.

Poor RAG content:

- Giant multi-megabyte files inserted as one chunk.
- Duplicate boilerplate.
- Policy facts that should be OKF instead.
- Content without source labels.
